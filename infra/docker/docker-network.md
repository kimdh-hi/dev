# docker network

## docker networking

- https://docs.docker.com/engine/network/
- docker 의 핵심은 격리이다.
- docker container 는 자신만의 파일시스템, 프로세스 공간, `네트워크 공간`을 가진다.
    - 컨테이너는 호스트나 다른 컨테이너와 분리된 자신만의 네트워크 인터페이스, ip주소, 라우팅 테이블을 갖는다.
    - 즉, 기본적으로 컨테이너A 와 컨테이너B는 별도 설정이 없는 경우 `직접 통신 불가` (default bridge 와 같은 기본 장치가 없는 경우)
- docker network 는 격리된 각 컨테이너 사이 통신 경로를 만들어주는 장치

## docker network driver

- https://docs.docker.com/engine/network/drivers/
- docker 의 네트워킹 시스템은 드라이버 방식으로 동작
    - 네트워킹을 어떤 방식으로 구현할지는 driver  가 결정
- 기본 제공 드라이버 5종
    - Bridge (default)
        - 동일 docker 호스트 상 컨테이너 통신시 사용
        - user-defined bridge 만들면 컨테이너 간 이름으로 통신 가능
    - host
        - 컨테이너와 호스트 사이 네트워크 격리 제거
        - 포트 매핑, NAT 등 오버헤드가 없어서 성능 개선시 사용 가능
        - 단, 격리가 없어지므로 포트 충돌 위험 등이 있음
    - overlay
        - 여러 docker 데몬(호스트)를 연결해 서로 다른 호스트의 컨테이너 간 통신 간으
        - OS 수준의 라우팅 없이 다중 호스팅 통신이 가능하여 주로 Swarm 환경에서 사용
    - none: 네트워킹 완전 비활성화 (호스트, 다른 컨테이너로부터 완벽히 격리)

## docker network bridge

- https://docs.docker.com/engine/network/drivers/bridge/
- bridge 는 일반적으로 네트워킹 용어에서 서로 다른 네트워크 사에이서 세그먼트 트래픽을 전달하는 링크 계층 장치이다.
- docker 에서 bridge 네트워크는 소프트웨어 브리지를 의미한다.
- Docker Engine 시작시 Linux 호스트 쪽에 `docker0` 라는 이름의 소프트웨어 브리지가 자동 생성된다.
    - `docker0`: 일종의 가상 스위치
    - `해당 브리지에 연결된 컨테이너끼리는 통신 가능`하고, 연결 되어있지 않은 경우 격리된 채 통신 불가

```
1. 컨테이너 실행시 컨테이너에 가상 네트워크 인터페이스 생성 (보통 컨테이너 내에서 `eth0` 로 조회됨)
2. `eth0` 가상 네트워크 인터페이스는 호스트 쪽의 `docker0` 브릿지에 연결
3. 같은 bridge 에 연결된 컨테이너들은 해당 브릿지를 통해 패킷을 주고 받음
4. docker bridge driver(docker0) 는 호스트(iptables..) 규칙을 자동 설치하여 서로 다른 브리지 네트워크에 연결된 컨테이너 간 통신 불가하도록 격리

단, bridge 네트워크는 같은 docker host(같은 데몬) 위 컨테이너 대상으로만 적용됨
동일 서버 내 docker container 대상으로만 적용
```

### docker default bridge test

```
$ docker network ls
NETWORK ID     NAME      DRIVER    SCOPE
17e324f45964   bridge    bridge    local
6ed54d316334   host      host      local
7092879f2cc8   none      null      local
```

- name: bridge: default bridge

```
$ docker run -dit --name alpine1 alpine ash
$ docker run -dit --name alpine2 alpine ash
```

- 네트워크 별도 지정(`network`)하지 않는 경우 `두 컨테이너는 모두 default bridge 에 연결`
- alpine1 에서 alpine2 의 ip 주소로 ping 시 성공
    - `docker network inspect bridge` 통해 ip 확인 가능
- 단, `alpine2` 라는 이름으로는 ping 불가.
    - default bridge 는 기본적으로 ip 로만 접근 가능하고 이름으로는 접근 불가.
- default bridge 는 별도 내장 DNS(127.0.0.11) 을 사용하지 않고, 호스트의 `/etc/resolv.conf` 의 사본만 받아서 사용
    - 호스트의 `/etc/resolv.conf` 는 컨테이너 이름, ip 매핑정보가 없으므로 실패

## user-defined bridge

- default bridge 는 컨테이너 이름으로 네트워크 접근이 불가함
    - 컨테이너는 매 재시작마다 IP 가 바뀔 수 있으므로 IP 로 참조는 불안정

### user-defined bridge test

- https://docs.docker.com/reference/cli/docker/network/create/

```
$ docker network create my-net
$ docker run -dit --name app1 --network my-net alpine ash
$ docker run -dit --name app2 --network my-net alpine ash

# bridge가 기본 드라이버이므로 -d bridge는 생략 가능
```

- docker host 에 `docker0` 와 별개의 linux bridge 하나 더 생성

```
# 동일 네트워크(브리지)에 연결된 컨테이너 이름으로 호출 가능
docker exec app1 ping -c1 app2
```

- docker 내장 DNS서버(127.0.0.11)가 컨테이너 이름을 해당 컨테이너의 현재 IP로 변환
    - 내장 dns 서버 확인 `docker exec my-app cat /etc/resolv.conf`
    - 결과
        
        ```
        # Generated by Docker Engine.
        # This file can be edited; Docker Engine will not make further changes once it
        # has been modified.
        
        nameserver 127.0.0.11
        options ndots:0
        
        # Based on host file: '/etc/resolv.conf' (internal resolver)
        # ExtServers: [host(192.168.5.2)]
        # Overrides: []
        # Option ndots from: internal
        ```
        
    - 127.0.0.11 에 해당하는 DNS 서버는 Docker 데몬의 일부로써 해당 질의는 데몬의 내장 DNS 가 받아 처리.
    - 결국 docker 데몬이 컨테이너 이름을 받아서 IP로 변환하여 응답해주는 구조.
    - 내장 DNS 로부터 질의 실패한 경우  호스트의 DNS (host `/etc/resolv.conf`) 로 질의
- https://docs.docker.com/engine/network/#dns-services

## 컨테이너 outbound 통신

- https://docs.docker.com/engine/network/packet-filtering-firewalls/
- bridge 네트워의 컨테이너는 `masquerading`(NAT의 한 종류)을 사용
- 도커 호스트에 인터넷 연결이 있는 경우 별도 설정없이 컨테이너도 외부 인터넷 접속 가능 (외부 네트워크 아웃바운드 가능)

```
$ docker run --rm -ti busybox ping -c1 docker.com
```

- 위 경우 컨테이너의 패킷은 브리지를 거쳐 호스트의 IP로 출발지 주소가 바뀌어 외부로 나감 (=`masquerade`)

## 컨테이너 inbound 통신

- https://docs.docker.com/engine/network/port-publishing/
- 기본적으로 호스트 외부에서 컨테이너 포트로 직접 접근 불가
- 필요시 포트 매핑 필요
    - `docker run -d -p 8080:80 nginx`
    - 외부에서 호스트로 들어온 8080 을 컨테이너 내 80 포트로 전달

## docker compose network

- docker-compose.yml 작성시 networks 를 따로 명시하지 않아도 `<프로젝트이름>_default` 이름의 docker network 가 생성됨
    - 프로젝트이름: compose 파일 위치한 디렉토리 이름
- 기본 생성되는 docker network (bridge driver)
- 즉, 기본적으로 user-defined bridge 를 갖는다.

### docker compose custom network

```yaml
services:
  proxy:
    image: example/proxy
    networks:
      - frontend
  app:
    image: example/app
    networks:
      - frontend
      - backend
  db:
    image: example/db
    networks:
      - backend

networks:
  frontend:
    driver: bridge # bridge가 default 생략 가능
  backend:
```

- app: 동시 n개 network 연결 가능
- proxy, db 통신 불가
