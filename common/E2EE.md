# E2EE

## E2EE (End-to-End Encryption)

- E2EE는 암/복호화가 오직 양 끝단에서만 일어나고, 중간 그 어떤 경로에서도 평문을 볼 수 없는 상태를 말한다.
- 대칭키 암호화 방식 사용
    - 대칭키 암복호화 시 필요한 키는 키 합의 알고리즘 연산 통해 획득
    - 키 합의 알고리즘은 X25519 (Diffie-Hellman, DH) 사용

## 키 교환

- 각 기기는 개인키, 공개키 페어를 생성
- 각 기기는 서로의 공개키와 본인의 개인키를 통해 공유키 계산
    - 공유키 계산은 마이크로초 수준의 연산이므로 필요할 때 연산하고, 각 기기 로컬에서 관리

```
X25519 키 교환 (단순하게)
- 실제는 타원곡선을 사용하는 복잡한 방식으로 연산

1. 개인키 생성
- deviceA: 6
- deviceB: 15

2. 특정 규칙에 따라 공개키 생성
- 규칙: 5^(개인키) mod 23
- deviceA: 5^6 mod 23 => 8(공개키)
- devceB: 5^15 mod 23 => 19(공개키)

3. 공개키 교환
- 상대방의 공개키를 어떤 경로로든 획득

4. 공유키 계산
- 원리: (5^a)^b = (5^b)^a  → 양쪽이 같은 5^(a*b) 도달
- deviceA: deviceB의 공개키 19에 본인의 개인키 6 적용
  - 19^6 mod 23 => 2(공유키)
- deviceB: deviceA의 공개키 8에 본인의 개인키 15 적용
  - 8^15 mod 23  => 2(공유키)

암호문 = 암호화(메세지, 공유키)
메세지 = 복호화(암호문, 공유키)
```

## 간단 적용 예시

### 메세지 발신시

1. 공개키/개인키 페어 생성
2. 앱 설치 후 서버에 device 등록시 공개키 등록
3. 메세지 발신시 수신자의 공개키 서버로부터 조회하여 공유키 생성 (로컬에 있는 경우 해당 공유키 사용)
4. 공유키 통해 암호화 후 전송

### 메세지 수신시

1. 공개키/개인키 페어 생성
2. 앱 설치 후 서버에 device 등록시 공개키 등록
3. 메세지 수신시 발신자와의 공개키 서버로부터 조회하여 공유키 생성 (로컬에 있는 경우 해당 공유키 사용)
4. 공유키 통해 복호화 및 로컬 db 에 저장

## X3DH

- X3DH: Extended Triple DH
- 일반적으로 키 교환은 공개키를 주고받기 위해 두 종단 사용자가 접속해 있어야 함
    - 새벽에 A → B 메세지 발송하고 싶은데 B가 접속중이아니면 B의 공개키를 가져갈 수 없어서 공유키 계산못하므로 메세지 발송 불가
    - 해결: B의 공개키를 서버에 등록한다.
    - 서버에 등록한 공개키를 prekey 라고 한다.
- 공개키를 하나만 두는 경우 개인키가 유출되는 경우 과거 데이터들 전부 복호화 가능
    - 3개 종류 키 생성 및 등록
    - IK (신원키): 신원을 인증
    - SPK (서명된 prekey): 몇주~몇달 단위로 회전
    - OPK (일회용 prekey): 한 번 쓰고 버림
- DH 4번 (Diffie-Hellman 4번)
    - A → B 메세지 발송시
    - A: IK_A(고정), EK_A(1회용)
        - A가 서버로부터 조회한 것: IK_B, SPK_B, OPK_B

```json
DH1 = DH(IK_A,  SPK_B)    ← A의 고정키 사용
DH2 = DH(EK_A,  IK_B)     ← B의 고정키 사용
DH3 = DH(EK_A,  SPK_B)    ← 양쪽 다 고정x
DH4 = DH(EK_A,  OPK_B)    ← 양쪽 다 1회용

SK = KDF(DH1 || DH2 || DH3 || DH4)
```

- **DH1** — A의 고정 개인키가 있어야 계산 가능 → B이 "진짜 A가 보냈네"를 확인
- **DH2** — B의 고정 개인키가 있어야 계산 가능 → A가 "진짜 B만 풀 수 있네"를 확인
- **DH3, DH4** — 쓰고 버리는 키만 씁니다. → 나중에 고정키가 털려도 이 값은 복원 불가

```json
전체 흐름 (5줄 요약)
B: 자기 전에 공개키 묶음(IK, SPK, OPK 여러 개)을 서버에 올려둠
A: 서버에서 B의 공개키 묶음을 받아옴 (B은 여전히 자는 중)
A: 임시키 EK를 만들고 → DH 4번 → SK 계산 → SK로 암호화해서 전송
B: 아침에 일어나 메시지 수신. 메시지 안에 A의 공개키들이 들어 있음
B: 같은 DH 4번을 자기 개인키로 반복 → 똑같은 SK가 나옴 → 복호화
```
