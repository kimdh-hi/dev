# 프로퍼티 민감정보 암호화용 키관리

```
node:crypto, jasypt 와 같은 프로퍼티 암호화 라이브러리 통해 민감정보 암호화
```

## 방안1. MEK(Master Encryption Key) 통한 암복호화

- 실제 .env, application.yml 에는 암호화 키 포함되지 않음
- 별도 배치 복호화 지원되지 읺는 경우 매 부팅시 민감정보 값마다 vault, kms 등 측으로 복호화 api 호출 필요
- MEK 회전 후 이전 키버전 폐기시
    - 암호화 된 모든 민감정보 프로퍼티 재암호화 필요
    - 단, 폐기 전까지는 사용 가능

## 방안2. DEK(Data Encryption Key) 통한 암복호화

- MEK 로 암호화 된 EDK(wrapped DEK) 를 .env, application.yml 에 포함하여 commit/push
    - EDK 만으로는 복호화 불가
    - EDK를 MEK로 복호화한 DEK 값으로 암호화된 민감정보 프로퍼티 복호화 가능
- MEK 로 EDK 복호화 vault, kms 등 api 호출 1회로 복호화된 DEK 받아서 복호화 연산 가능
- MEK 회전시
- MEK 회전시 EDK 는 다시 암호화 필요하여 env에 명시된 EDK 수정 필요
    - 단, MEK 는 append 방식으로 회전하므로 키 폐기 전까지는 EDK 도 계속 사용 가능
    - 이전 MEK(이전 키버전) 폐기시 EDK 재암호화 및 env 에 명시된 값 변경 필요
- MEK 회전 및 폐기에 의해 EDK 변경시 실제 env 민감정보 암호화에 사용되는 DEK 에는 영향없으므로 모든 프로퍼티 재암호화 불필요
    - 단, DEK 회전 필요한 경우 모든 암호화 프로퍼티 재암호화 필요

```
MEK: vault 에서 관리하는 key
DEK: 실제 프로퍼티 민감정보 암/복호화시 사용되는 대칭키
EDK: DEK 를 MEK 로 암호화한 값 (실제 git 에 노출되는 키 값)
```
